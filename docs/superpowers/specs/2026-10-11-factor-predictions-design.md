# 要素別の予想（予想家型）設計

2026-10-11。所有者と合意した設計。**拘束力のある仕様**。

## 1. 目的と範囲

### 1.1 目的

予想家が「自分の重視する要素」を持つように、**1つの要素だけで作る予想**を要素ごとに出し、どの要素が
**市場（人気）に上乗せできるか**を確かめる。効果の見えた要素を残していく。

- 判定の基準は「**市場に上乗せできるか**」（所有者の選択）。人気（単勝オッズ）だけの予想にその要素を
  足したとき、当たり方が良くなるか
- 判定の**根拠**として、要素単独の予想と市場の予想の的中数の比較（案B）も出す（所有者の希望）
- 検証は「**過去10年で絞り、これからのレースで確かめる**」（所有者の選択）

### 1.2 作るもの

- 15要素の点数を出す部品（§3）
- 市場だけの着順モデルと、市場＋1要素の着順モデル（§4）
- 過去（2017〜2025年）での評価とレポート（§5）
- これからのレースでの発走前の記録と、答え合わせ（§6）

### 1.3 作らないもの

- Jev・Cloudflare の意思決定モデルなど外部モデルの要素（所有者の判断で今回はなし。差し込み口だけ用意する。§7）
- 調教タイム（今のデータ版に無い）
- 全要素をまとめた1つのモデル（効果のある要素がそろってから別の仕様で）
- 馬券の買い目・回収率の評価
- 既存の予想（6パターン・案A/B・統計）と各種の版の変更

## 2. 用語

| 用語 | 意味 |
|---|---|
| 要素 | 出走馬1頭ごとに点数を出す部品。大きいほど3着内に来やすい向き |
| 版 | 要素の定義の版（`v1` など）。結果を見てから定義を変えるときは版を上げ、前の版の記録は書き換えない |
| 時点 | 予想する時点。過去の評価では**そのレースの日の 0:00（日本時間）**。その日より前のデータだけを使う |
| 市場 | 単勝オッズ。過去の評価では確定オッズ（SE の `result_odds`）、これからの記録では締切前のオッズ（JVRTOpen `0B31`） |
| 見込み3着内率 | 人気順位ごとの3着内率（時点より前のデータで作る表）。「人気から見込まれるより何回多く来たか」の基準 |
| A−E | 実際の3着内（1/0）− 見込み3着内率。表の要素（騎手など）の材料 |
| 縮小 | 頭数の少ない組の平均を全体平均へ寄せる経験ベイズ（世代レベルの §3.2 と同じ考え方） |

## 3. 要素の部品

### 3.1 形

```python
class Factor(Protocol):
    name: str          # 例 "jockey"
    version: str       # 例 "v1"
    forward: bool      # これからの記録で朝に出せるか（馬体重は False）
    def scores(self, race: RaceContext, *, as_of: datetime) -> dict[str, float | None]: ...
```

- `as_of` はキーワード専用・既定値なし（`Repository` と同じ約束）。**`as_of` 以降のデータは一切使わない**
- 返す値は馬番 → 点数。分からない馬は `None`。市場モデルに入れるときは `None` をそのレースの平均で埋める
- 過去10年の評価を現実的な時間で回すため、実装は「全レース分の点数をまとめて計算する関数」を持ってよい。
  その場合も、各レースの点数はそのレースの日より前のデータだけから作られていることをテストで保証する（§9）

### 3.2 15要素の定義（v1）

| # | 名前 | 点数 |
|---|---|---|
| 1 | `time_figure` タイム指数 | 時点より前1年の指数（世代レベルの物差し）の上位2走の平均。基準タイムとクラス差は時点の年の前年末までのデータで推定し、馬場差はその日の古馬戦だけで（基準・クラス差を固定して）推定する |
| 2 | `opponents` 相手関係 | 過去5走（1年以内）の各走の「その走の他の出走馬の、当時の指数（上位2走平均）の平均 − 自分の着差（1600m 換算の秒）」の、上位3走の平均 |
| 3 | `jockey` 騎手 | 時点より前の全騎乗の A−E の縮小平均 |
| 4 | `trainer` 調教師 | 同じく管理馬の A−E の縮小平均 |
| 5 | `sire_surface` 父の芝・ダート適性 | （父, 今回の芝ダ）の産駒の A−E の縮小平均 |
| 6 | `late_age` 晩成度 × 年齢 | 父の晩成度 L × 年齢係数。L は晩成の2物差し（長い期間の伸び、出世の時期）の父ごとの縮小効果をそれぞれ標準化して平均したもの。物差しの材料は時点の年の前年末までに5歳前半を終えた世代だけ。年齢係数 = clip(年齢 − 3.5, −1.5, +1.5) |
| 7 | `age` 年齢 | 年齢曲線（時点の年の前年末までのデータ）の、その馬の年齢・半期の水準 |
| 8 | `cohort_level` 世代レベル | その馬の世代の例年比（中央値）。時点の月の1日の 0:00 を時点として計算した値（月ごとに更新） |
| 9 | `distance_fit` 距離適性 | 今回の距離 ±200m の過去走の「1 − 着順の割合」の平均（着順の割合 = (着順 − 1) / (頭数 − 1)） |
| 10 | `course_fit` コース適性 | 同じ競馬場・同じ芝ダの過去走の同じ値 |
| 11 | `draw` 枠順 | （競馬場, track_cd, 距離, 枠番）の過去の3着内率 − 同じ（競馬場, track_cd, 距離）の3着内率、の縮小値 |
| 12 | `weight_carried` 斤量 | −（斤量 − そのレースの平均斤量） |
| 13 | `layoff` 間隔 | 前走からの日数の区分（〜13 / 14〜27 / 28〜55 / 56〜118 / 119〜364 / 365〜 / 初出走）ごとの A−E の縮小平均 |
| 14 | `body_weight` 馬体重 | 前走からの増減の区分（〜−10 / −9〜−4 / −3〜+3 / +4〜+9 / +10〜 / 不明）ごとの A−E の縮小平均。**`forward = False`** |
| 15 | `travel` 遠征 | （所属トレセン, 開催地域）ごとの A−E の縮小平均 |

- 表の要素（3〜5, 11, 13〜15）は、**時点の前日までのデータ**で作る（累積和で計算できる）
- 過去走が無い馬は、過去走を使う要素（1, 2, 9, 10）で `None`

## 4. 着順モデル

### 4.1 市場だけ

スプリンターズS（`tmp/keiba-report/sprinters2026/combine.py`）と同じ**段ごとの条件付きロジット**。

- 段 s = 1, 2, 3 ごとに、残った馬の中から s 着の馬が選ばれる確率を `softmax(w_s · x)` とする
- 市場の特徴 x = [log q, (log q)²]。q はレース内で正規化した 1/単勝オッズ
- 1〜3着の順番の確率から、各馬の1着確率・3着内確率を出す

### 4.2 市場＋1要素

上の x に、その要素の点数をレース内で中心化し、全体の標準偏差で割った z を1列足す。段ごとに重みを持つ。

### 4.3 重みの推定

- **評価する年 Y の重みは、Y より前の年（2016年〜Y−1年）だけで推定する**（拡大窓）
- 要素の点数も、学習に使う年の分は §3 の時点の規則で作る

## 5. 過去での評価

### 5.1 データ

- 長いデータ版 `data/_long/versions/20261010T155433Z`（2015-01〜）。JRA10場の平地、確定成績（`data_kubun` 7）
- **評価する年は 2017〜2025年**。2015〜2016年は表と重みの助走
- 2026年1〜9月は統計分析の一度きりの検定で使用済みなので評価に入れない
- 1着〜3着が一意に決まらないレース（同着）と、単勝オッズが無い馬のいるレースは除き、件数をレポートに出す

### 5.2 判定（案A）

要素ごとに、評価年の各レースで

- `Δ` = 市場だけの −対数尤度（1〜3着の順番）− 市場＋要素の −対数尤度。**正なら上乗せあり**
- 9年まとめた平均 `Δ` と、開催日単位のクラスタ・ブートストラップの 95% 区間（1,000 回、種 20261011）
- 年ごとの平均 `Δ` と、9年中 `Δ > 0` の年の数

**判定のルール（固定）**: 「9年まとめた区間が 0 を含まない（下限 > 0）」**かつ**「9年中7年以上で `Δ > 0`」のとき
**上乗せあり**。それ以外は「上乗せは確認できない」。15要素を同時に調べるので、年ごとの安定性も条件にしている。

### 5.3 根拠（案B）

- **単独の的中**: 要素の点数だけで選んだ上位3頭の、3着内の頭数の平均 vs 市場（人気上位3頭）の同じ値
- **市場＋要素の的中**: 市場＋要素の3着内確率の上位3頭 vs 市場だけの上位3頭
- **食い違いの表**: 要素の上位3頭にいて市場の上位3頭にいない馬と、その逆の馬の、頭数・実際の3着内率・見込み3着内率
- どれも 9年まとめと年ごと

### 5.4 内訳

全レースのほか、「OP・重賞」と「3歳以上の古馬混合戦」でも §5.2・§5.3 を出す（内訳には判定を付けない。参考）。

### 5.5 出力

`data/factor_eval/<実行日時>/`: `report.md`（判定・根拠・内訳・年ごと）、`summary.csv`、`by_year.csv`、
`manifest.json`（データ版、評価年、要素の版、種、実行時刻）。

## 6. これからのレースでの記録

### 6.1 対象と時期

- 毎週末の JRA の全レース
- **レース当日の朝に1回**記録する。その時点の締切前オッズを使う
- 馬体重（`forward = False`）は v1 では記録しない。過去で「上乗せあり」になったら、発走直前に記録する仕組みを別に足す

### 6.2 手順

1. 最新の出馬表を JV-Link（option 1）で取り、長いデータ版に重ねた作業用の版を作る（毎日王冠の `make_merged.py` を道具にしたもの）。本番の CURRENT は変えない
2. 対象日の各レースの締切前オッズを JVRTOpen `0B31` で取る
3. 全要素（`forward = True` の14要素）について、単独の1〜3着、市場＋要素の各馬の1着・3着内確率を出す。重みは 2016〜2025年で推定したもの（§4.3 と同じ方法、評価年なし）
4. レースごとに1ファイルへ書く。**記録後は書き換えない**（同じファイルがあれば上書きせずエラー）

### 6.3 記録の中身

`data/factor_records/<YYYYMMDD>/<race_id>.json`:

- 記録時刻、オッズを取った時刻、データ版、要素の名前と版、市場モデルと各要素モデルの重みの版
- 馬ごと: 馬番、馬名、単勝オッズ、各要素の点数（`None` を含む）
- 予想ごと（市場、各要素単独、市場＋各要素）: 1〜3着、全馬の1着確率・3着内確率

### 6.4 答え合わせ

- 結果は JVRTOpen `0B12`（速報成績）か蓄積系の確定成績で取り込む
- `data/factor_records/report.md` に要素ごとの成績表（§5.2・§5.3 と同じ数字）を出す。**10レースごとに見られる**
- **「これからのレースで確認できた」の判定は一度だけ**、記録が **300レース**に達した時点で、過去で「上乗せあり」に
  なった要素だけについて行う。ルールは「`Δ` の 95% 区間（開催日クラスタ・ブートストラップ）が 0 を含まない」
- 途中の10レースごとの表は様子を見るための参考で、判定には使わない

## 7. 外部モデルの差し込み口

§3.1 の形を満たし、`forward = True`・過去の評価なしの要素として、Jev や Cloudflare の意思決定モデルを後から足せる。
記録（§6.3）は要素の名前と版で区別するので、既存の記録の形を変えずに追加できる。v1 では作らない。

## 9. テスト

作り物のデータで、**テストを先に書いてから実装する**。

| テスト | 確かめること |
|---|---|
| 時点の規則 | 各要素の点数が、そのレースの日以降のデータを変えても変わらない（未来の結果をいじっても点数が同じ） |
| 欠損 | 過去走の無い馬は `None`、モデルではレース平均で埋まる |
| 縮小 | 1件だけの組は全体平均に近く、多い組は自分の平均に近い |
| 表の要素 | 仕込んだ A−E（例: ある騎手が人気より多く来る）を取り戻せる |
| 着順モデル | 仕込んだ重みを取り戻せる。1〜3着の確率の合計が 1 |
| 上乗せの判定 | 効く要素を仕込んだ作り物では「上乗せあり」、雑音だけの要素では「確認できない」 |
| 拡大窓 | 評価年 Y の重みに Y 年のレースが使われない |
| 食い違いの表 | 手計算と一致する |
| 記録の書き換え禁止 | 同じ race_id の記録があれば上書きせずエラー |
| 馬体重 | `forward = False` の要素は記録に入らない |

## 10. 既知の弱点

- 過去の評価は確定オッズ、これからの記録は朝のオッズ。朝のオッズは締切までにかなり動くので、市場の基準が弱くなり、
  要素の上乗せが過去より大きく見えやすい
- 15要素を同時に調べるので、偶然の「上乗せあり」が混じりうる（年ごとの安定性の条件で和らげている）
- 市場は既に多くの要素を織り込んでいる（これまでの統計分析では、ほぼ全変数の差が市場との比較で消えた）。
  「上乗せあり」が少数、または0個で終わる可能性は高い
- 世代レベル（#8）は過去の世代が少ない年ほど粗い
- 300レースでも、小さな上乗せ（対数損失で 0.01 未満）は検出できないことがある
